# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

方块快跑 ("Block Run") is a browser survival game built with vanilla JavaScript and the HTML5 Canvas API. There is **no build system, no bundler and no test suite**. The game itself lives in three files: `index.html`, `style.css`, and `game.js` (~5600 lines, all logic). Optional online co-op uses a small Node WebSocket relay, `server.js` (its only dependency is `ws`, declared in `package.json`).

UI strings and code comments are in Chinese.

## Running the game

Open `index.html` directly in a browser, or serve the directory statically (e.g. `python -m http.server 8000` then visit `http://localhost:8000`). A static server is preferable for testing touch/responsive behavior with device emulation.

The page opens on a DOM lobby (`#mpOverlay`): **单人游戏** starts a local run; **创建房间 / 加入** need the relay. For co-op, run `npm install && npm start` (listens on port 8080), serve the directory over HTTP, and open the page in two browsers. The client connects to `ws://<page hostname>:8080`, or to a URL given in the hash (`index.html#ws://host:port`).

There is no lint or test command (`node --check game.js` catches syntax errors). Verify changes by playing the game in a browser, including mobile/portrait emulation (see "Responsive & touch" below), and a host+guest pair when touching multiplayer.

The `.trae/documents/` file about NPM global directory config is unrelated to this game.

## Bootstrap

`game.js` is loaded via `<script src="game.js">`. All classes are global (no modules). On `window load`, the handler does `new Game()`, `game.render()`, and wires the lobby buttons (create/join/start/single/restart/back-to-lobby). The `Game` constructor calls `init()`, which calls `bindEvents()` to wire all DOM/canvas/keyboard handlers and must run for the game to be interactive. Top-of-file globals: `DT` (fixed step in seconds), `CLASS_BASE_CD` / `CLASS_BASE_ADJUST` (class tuning), `roundRect()` (shared canvas path helper), `SpriteCache`, `Store` (safe `localStorage`), `Sound` (WebAudio sound effects), `nextEntityId()`, and the multiplayer quantize helpers/type tables (`q1`, `q2`, `MP_ENEMY_TYPES`, `MP_ITEM_TYPES`).

> **Known gotcha:** the bootstrap path is fragile — `init()` is the single place every event listener is registered. If the start/pause buttons, click-to-move, or Q/E keys ever go dead, confirm `init()` actually runs (it must be invoked from the constructor or the load handler). A missing `init()` call silently produces a fully-rendered but completely unresponsive game.

## Architecture

- **`Game`** — orchestrates everything. Runs the loop in `startGame()` with `requestAnimationFrame` and a **fixed-step accumulator**: `update()` runs once per 16ms of elapsed time (max 10 catch-up steps per frame, elapsed capped at 100ms), then `render()` once per animation frame. Owns game state (`life`, `level`, `exp`, `score`, `gameTime`, `difficulty`), entity arrays (`enemies`, `items`, `projectiles`, `effects`, `particles`), the animated background (`stars` + grid via `bgTime`), the **boss scheduler**, and the **talent system**. Also drives the **base auto-attack** (`_tickAutoAttack()`, using the player's own `autoAttackTimer` / `autoAttackInterval`, ~0.6s) routed through `shoot()`, whose behavior depends on class (see "Skills & classes").
- **`Player`** — stats, movement (WASD/arrows *or* click/tap-to-move via `targetX/targetY`), the 5-class system, per-class resources, and survival timers (`hurtCooldown` i-frames, `invincibleTimer`, `stunTimer`). Skills live in `skillQ` / `skillE`, each `{ cooldown, maxCooldown, level }`.
- **`Enemy`** — six types with distinct AI: `chaser` (追, homes on player), `patroller` (巡, patrols then chases within range), `giant` (巨, moves then rests), `gunner` (炮, stationary near the edge, periodically fires an `EnemyBullet` at the player; rendered by `_renderGunnerTop`), `dasher` (冲, approaches, winds up, then dashes a fixed `dashDist` along a locked line; 1.5× contact damage mid-dash, stun interrupts the wind-up) and `bomber` (爆, lights a fuse near a player and explodes in `blastRadius`, hurting players and enemies; if killed first it detonates harmlessly to players via `_onEnemyKilled(e)` → `_bomberExplode(e, false)`, which can chain). Dasher/bomber share `state`/`stateTimer`/`stateDur` (0 approach, 1 wind-up/fuse, 2 dash, 3 recover); state 1 draws a ground telegraph in `Enemy.renderTelegraphs` (fills only, under all enemies). There is also the event-only `treasure` enemy and the `elite` variant (see "Random events"). Enemies chase the nearest living player (`_nearestPlayer`, guests included). All stats scale by `difficulty`. Has a `stunTimer` (set by mage/paladin skills) that freezes its AI. Spawn weighting is in `spawnEnemies()` (chaser 44 / patroller 24 / gunner 15 / giant 5, plus dasher 8 after 30s and bomber 8 after 50s); each new type's first appearance per run shows a one-time hint (`_introduceEnemy`, `Enemy.INTROS`). No spawns while a boss is active/retreating, and none once `enemies.length` reaches `maxEnemiesFor(difficulty)` (50 → 80). Kill sites pass the enemy to `_onEnemyKilled(e)`.
- **`BlockBoss` (方块大魔王)** — a periodic boss, **stored in `this.boss`, NOT in the `enemies` array**. It doesn't truly die; the fight ends by "repel" (see "Boss system"). Because it lives outside `enemies`, every targeting/collision/damage path special-cases it.
- **`Item`** — 6 timed pickups (`potion`, `snowflake`, `bomb`, `heart`, `potion_invicible`, `exp_book`) with rarity tiers (common/rare/epic), rarity-based lifetimes (shorter = rarer), a drop-in landing animation, lifetime-warning flicker, and pickup burst feedback. Effects handled in `Game.collectItem()`; weighted spawn in `spawnItems()`.
- **Timed gear (限时装备)** — four `gear_*` `Item` types (`GEARS` / `GEAR_TYPES` table at the top: 雷霆之刃 blade, 烈焰法球 orb, 寒霜战甲 armor, 风暴连弩 bow). Drops every 25–35s (`gearTimer` in `spawnItems`) and always on boss repel (`_dropGear`); guests can pick items up too (`_checkGuestCollisions`, except `potion_invicible`). Picking one sets `player.gear = { type, timer, max, cd, angle }` via `_equipGear` (same type refreshes, another type replaces). Stat effects are **read at use sites, never baked into base stats** (guests' base stats are overwritten by their `stats` input): `atkMult` in `_computeAttackDamage`, `defBonus` in `Player.takeDamage`, `speedMult` in `Player._move`. `_tickGear()` (called from `_tickPlayerResources`, so per guest under `_runAsPlayer`) counts down and runs the special attack: chain `lightning` effect, orbiting fireballs (`Game.ORB_SPIN`/`ORB_RADIUS`), frost nova that stuns, or a 5-bolt fan (`Projectile.gearBolt`, snapshot kind 2). Damage goes through `_gearHit` (no rage). Snapshot player field `g` → `_mpGear`; drawn by `_renderGearAura` (player ring + time arc + fireballs) and `_renderGearHUD` (under the stats panel).
- **`Projectile`** — basic auto-attack/ranged bullet carrying a `damage` field; supports optional piercing (`isPiercing` / `pierceRemaining` / `hitEnemies` Set) used by the archer.
- **`PiercingArrow`** — archer Q projectile that runs its **own collision detection in `update()`** (it holds a `game` ref), hitting each enemy once via a `hitEnemies` Set and damaging the boss directly.
- **`EnemyBullet`** — gunner projectile (`vx`/`vy`, `angle`, `trail`), stored in `Game.enemyBullets` and checked against the player in `checkCollisions()`.
- Every entity class (`Enemy`, `Item`, `Projectile`, `PiercingArrow`, `EnemyBullet`) gets a unique `id` from `nextEntityId()` in its constructor; multiplayer sync depends on it.

### Skills & classes

Five classes, chosen on a canvas menu at level 3 (`renderClassSelection` / `handleClassChoice`). Each has a **Q** and **E** skill keyed to the `q`/`e` keys (`castSkillQ` / `castSkillE` dispatch to `_<class>Q` / `_<class>E`). Skills have **levels 1–3**; level scales damage via `_getSkillMultiplier()` (1.0 / 1.2 / 1.5) and cooldown via `_getCDMultiplier()` (1.0 / 0.85 / 0.7), upgraded by the `skillQUp` / `skillEUp` talents.

Each class uses a distinct **resource** (rendered as a side bar in the skill HUD, and surfaced in the DOM `mana`/`maxMana` row which is repurposed per class):
- **warrior** — `rage` (0–100, gained on attack/hurt/kill via `gainRage`, decays ~2/s); melee aura auto-attack (`_warriorMeleeAttack`), no ranged auto-attack.
- **mage** — `mana` (regen `manaRegen`); Q is a **toggle** ("魔力涌注") that makes each auto-attack cost ~10% maxMana and add `maxMana×1.5` magic damage; E is an AoE freeze nova (`stunTimer`).
- **assassin** — `assassinCharge` (built by **moving**; consumed for a damage multiplier via `_consumeAssassinCharge`); Q blinks to target, E multi-strikes.
- **archer** — `arrows` (consumed per skill; empties → `reloadTimer` reload cycle; `_consumeArrows` rejects casts mid-reload); last-arrow Q deals ×2; auto-attack supports multishot/piercing/speed talents.
- **paladin** — `faith` (regen) **and** a passive regenerating `shield` (caps at `maxHealth × shieldCapRatio`); E is a self-centered holy aura that ticks heal+damage each frame while active; no ranged auto-attack.

Damage routing helpers: `_computeAttackDamage()` applies the `wrath` talent (more attack as HP drops); `_dealDamage()` applies damage, grants warrior rage, and **special-cases the boss** (accumulate `bossDamageDealt` instead of killing); `_onEnemyKilled()` is the single kill-settlement entry (score ×`scoreMult`, +5 exp, life-steal, +rage, `checkLevelUp`).

### Talent system

Replaces the old fixed potential-point menu. On level-up (or boss-repel reward) the player spends potential points on a **3-card draft** (`showPotentialMenu` → `_rollTalentChoices(3)` → `renderPotentialMenu`). Talent definitions live in `_buildTalentDefs()`; each has `rarity` (common/rare/epic, drawn with weights 60/30/10), an optional `applicable(game)` gate (e.g. class-specific or skill-not-maxed), an `apply(game)` effect, and `stackable`/`maxStacks`. Talents are applied through `_applyTalent(def)`, which runs `apply(game)` and records the stack in **`this.player.acquiredTalents`** (`[{id,count}]`).

**Talent state is per player.** Personal effects live on the `Player`: base stats, `autoAttackInterval`, and every class multiplier/flag (`warriorSkillDmgMult`, `bloodRageStacks`, `mageMulticast`, `archerPiercing`, `paladinAuraDurationBonus`, …, with defaults in the `Player` constructor). Talent `apply`/`applicable` and skill code must read and write them as `g.player.X` / `this.player.X`. **Only team-wide effects stay on `Game`:** `scoreMult` (丰厚奖励), `expToNext`/`expGrowthMult` (速学), `maxLife`/`life` (传承). When adding a talent, decide which of the two it is. `handlePotentialChoice` re-rolls and keeps the menu open while points remain.

### Boss system (方块大魔王)

A state machine on `Game` (`bossState`: `idle → warning → active → retreating`) driven by `_updateBoss()`:
- **idle** — counts down `bossTimer` (default 60s).
- **warning** — `bossWarningDuration` (5s) of red-border + countdown + screen shake.
- **active** — boss chases the player. Ends ("repelled") when the boss HP hits 0, **or** accumulated `bossDamageDealt ≥ bossDamageRequired × difficulty`, **or** `bossActiveTimer ≥ bossDuration` (30s). Repel reward: +1 life (capped at `maxLife`), +1 potential point (opens talent menu), +100×`scoreMult` score.
- **retreating** — boss flies offscreen, then back to idle with `bossTimer` reset.

Boss HP = `2000 × difficulty`; contact attack = `max(50, playerMaxHealth×0.5)`. Normal enemy spawns pause during active/retreating.

**Boss attacks.** While active, `_updateBossAttacks(target)` runs a small state machine on the boss (`atk` = `charge` / `ring` / `slam`, `atkPhase` 0 = wind-up, 1 = release/recovery, `atkTimer`/`atkDur`, `atkAngle`, `atkCD`). The boss chases and aims at the nearest living player (`_bossTarget`, guests included). Every attack has a ground telegraph drawn by `BlockBoss.renderTelegraph` (fills/strokes only, no `shadowBlur`) under the boss: charge = a lane that tracks the target for the first 60% of the wind-up then locks, ring = spikes showing each bullet direction (bullets are ordinary `EnemyBullet`s), slam = a filling circle of `slamRadius`. Stunning the boss during a wind-up interrupts it. Choice is distance-weighted and never repeats. At half the damage goal or half the duration the boss **enrages** (`enraged`: faster, shorter cooldowns, two ring waves, larger slam). Attack hits on players go through `_bossHitPlayer` (same i-frames as contact). All attack fields ride in the snapshot's `boss` row so guests draw the telegraphs; sounds are edge-detected in `_sfxTick`.

### Random events (随机事件)

`GAME_EVENTS` / `EVENT_TYPES` (top of file) define four timed events, scheduled by `_updateEvents()` (host/single only, called after `_updateBoss()`): `eventTimer` counts down only while `bossState === 'idle'`, the next event never repeats the last one, and an event only starts if it can finish before the boss (`bossTimer >= dur + 4`, else retry in 2s). State lives in `this.event = { type, timer, dur, left }` (reset by `_resetEvents()`); `_startEvent` / `_endEvent` handle announcements and cleanup.
- **meteor (流星雨)** — `_spawnMeteor` pushes `{id,x,y,r,t,dur}` into `this.meteors` (some aimed near players); `_updateMeteors` → `_meteorImpact` hurts players via `_bossHitPlayer` and damages enemies. Drawn by `_renderMeteorMarks` (ground, before the player) and `_renderMeteorRocks` (clipped to the world).
- **treasure (宝藏方块)** — enemy type `treasure` (harmless: `contactDamage()` returns 0 and both contact paths skip it; flees in `Enemy.updateTreasure`). Killing it runs `_treasureReward` from `_onEnemyKilled` (gear + 3 items + score/exp); if the event times out it escapes.
- **elite (精英来袭)** — `_spawnElites` calls `Enemy.makeElite()` (×1.3 size, ×3 HP, gold frame + crown via `Enemy.eliteSprite`, gold HP bar); kills run `_eliteReward`. Ends early when no elite is left.
- **horde (怪潮)** — `spawnEnemies` ×3 spawn chance and +25 cap; `_onEnemyKilled` doubles score/exp.
Sync: snapshot `ev`, `mt` (meteors), `tk`/`ek` (treasure/elite kill counts, used by the `treasure1`/`elite10` achievements) and enemy flag bit 4 (= elite; guests call `makeElite()` on create). Guests tick meteor `t` and event `timer` locally in `_mpInterpolate`. The banner is `_renderEventHUD` (hidden during boss warning/active); the start sound is edge-detected in `_sfxTick`.

### Key cross-cutting concerns

- **Fixed frame time `DT`.** All gameplay timers count down in *seconds* by `DT` (= 0.016) per `update()` (`gameTime`, cooldowns, `enemyFreezeTimer`, `invincibleTimer`, `hurtCooldown`, `stunTimer`, item `duration`/`landTimer`, effect `ttl`, `screenShake`, resource regen `* DT`, giant `restTimer`). Per-frame movement (`speed`, projectile `dx/dy`) is in pixels per tick. `freezeEnemies(ms)` and `activateInvincible(ms)` still take milliseconds and convert.
- **Delayed actions go through `pendingActions`, never `setTimeout`.** Staggered hits (`_assassinE`, `_archerE`, the mage repulse) push `{ delay, fn }` onto `pendingActions`, ticked by `_tickPendingActions()` inside `update()`, so they pause with the game (level-up menus, auto-pause). Real `setTimeout` keeps firing while paused — don't use it for gameplay.
- **Effects & particles must be queued, not drawn inline.** Visuals are pushed into `effects` (typed: ring/shockwave/slash/arrow/holyAura/floatText/meleeSwing/iceShard, plus plain circles) via `addEffect`/`_showFloatingText`/`spawnSlashEffect`, and into `particles` via `spawnParticles`/`spawnHitParticles`/`spawnBurstRing`. They are drawn in `render()` (`_renderEffects`/`renderParticles`); `updateEffects`/`updateParticles` age them out. Do **not** draw during `update()` — `render()` begins by repainting the background and would erase inline draws.
- **Boss lives outside `enemies`.** Every place that targets, collides, or kills must handle the boss separately (see `_findClosestEnemies` which appends the boss, the boss branches in `checkCollisions`/`shoot`/skills, and `PiercingArrow.update`). When adding any attack, remember enemies vs. boss are two code paths.
- **Canvas-rendered menus drive input.** Class-selection and talent menus are drawn *on the canvas* (not DOM). The render methods reset `this.buttons = []` at the top each frame, then `drawButton()` / card rendering push hit-rects into it; `checkButtonClick()` reads then clears that array on click. Rebuilding every frame prevents hit-rects from accumulating while paused. Talent-card `choice` values are 1-based (card index), `0` = skip. Render and input handling are intentionally coupled.
- **UI layers.** The DOM stat panel `#gameUI` still exists and is refreshed by `updateUI()` every 100ms, but it is **hidden** (`display:none`) in the fullscreen layout. What players see in a run is canvas-drawn: stats panel top-left (`_renderStatsHUD`: lives/maxLife, level, exp bar, score, time — kept ≤100px wide so it clears the boss bar), skill HUD bottom-right (`_renderSkillHUD`, also the Q/E touch buttons via `skillButtons`), boss HUD top-center (`_renderBossHUD`), mute button top-right (`_renderMuteButton`, hit-rect in `muteButton`), pause overlay. DOM is used for the lobby (`#mpOverlay`) and the game-over dialog (`#gameOver`, incl. `#bestRecord`).
- **High-DPI canvas & sprite cache.** `resizeCanvas()` sizes the canvas backing store in *device* pixels (`devicePixelRatio`, capped at 2) and letterboxes the 800×600 world via `gameScale`/`gameOffsetX/Y`. Because `shadowBlur` is in device pixels and ignores transforms, `_patchShadowBlur()` makes the main `ctx.shadowBlur` multiply by `dpr` so glows look the same on any screen. Static, glow-heavy visuals are pre-rendered once into offscreen canvases through the global `SpriteCache` (rebuilt on resize): enemy bodies/labels, gunner barrel and frozen overlays (`Enemy.bodySprite` / `barrelSprite` / `frozenSprite`) and the background gradient + grid (`_buildBgLayers`). To change how an enemy looks, edit those static sprite builders, not `Enemy.render`; inside them use `SpriteCache.blur(v)` for `shadowBlur`. Enemies are drawn by `Game._renderEnemies` in three passes: bodies/barrels/white flash (`Enemy.render`), then every health/reload bar batched into one path per color (`Enemy.renderBars`), then stun stars and frozen overlays (`renderOverlays`). Unrotated sprites go through `SpriteCache.drawPx(ctx, sprite, x, y, snap)`, which draws at native pixel size snapped to device pixels so Skia does a plain copy instead of a filtered scale (several times faster); `snap` is `{a,e,f}` from `ctx.getTransform()`. The background layers use it too. Size a sprite's `pad` with `SpriteCache.padFor(blur)` (a fixed pad clips the glow on phones and wastes fill on desktop). `_renderEffects` avoids per-frame `shadowBlur` for large effects: fixed-shape glows (plain circle, holyAura) are glow-only sprites made with `SpriteCache.glowOnly` with the shape itself drawn as vectors on top, and rings whose radius animates (shockwave, ring, meleeSwing) get a radial-gradient Gaussian glow from `_fillArcGlow`. Small effects (slash, arrow, floatText, iceShard, ring ticks) keep `shadowBlur`, since at their size it is cheaper than a drawImage.
- **Pause.** P/Esc toggles; `visibilitychange` (tab hidden / app backgrounded) auto-pauses; window `blur` clears `keys` so movement doesn't stick. A tap/click anywhere resumes a plain pause (touch devices have no P key) — level-up/class menus also set `isPaused` but are handled by their own buttons first.
- **Sound.** `Sound` synthesizes all effects with WebAudio (no asset files). The `AudioContext` is created/resumed in `Sound.init()` from the first pointer/touch/key event (browser autoplay policy). Event sounds are played directly (`_onEnemyKilled` → kill, `collectItem` → pickup/bomb, `_showGameOver` → gameOver); state-change sounds (hurt/death/levelUp/skill/boss phases) come from `_sfxTick()`, which edge-detects `hurtCooldown`, `life`, `level`, skill cooldowns and `bossState` of the local player each tick so it works identically for host and guest. M key or the top-right button toggles mute (persisted in `localStorage` `blockrun.muted`).
- **Best record.** `_showGameOver(time, score)` (used by both `endGame()` and the guest's `game_over` message) stores max score/time in `localStorage` `blockrun.best`; the lobby shows it via `updateBestScoreLabel()`.
- **Onboarding & out-of-run progression.** First page load shows the DOM `#tipsOverlay` once (flag `blockrun.tutorialSeen`; the lobby's 玩法说明 button reopens it). Cross-run progress lives in `localStorage` `blockrun.profile` via the global `Progress` (runs, totalScore, totalTime, bossRepels, classesPlayed, achievements, selected skin). `ACHIEVEMENTS` (each `check(run, profile)`) and `SKINS` (unlocked by `need.totalScore` or `need.ach`) are top-of-file tables. In a run, `_progressTick()` (called right after `_sfxTick()`, so host and guest both run it) counts boss repels by edge-detecting `bossState`, checks achievements every 0.5s and shows local-only toasts (`achToasts`, drawn by `_renderAchToasts`, not pushed into `effects` so they are never synced). `_showGameOver` calls `_finishRunProgress()` to record the run once and list new unlocks in `#runUnlocks`. The local player's look comes from `player.skin` (set in `_initRunProgress()` at `startGame`); remote players still render with their per-id color.
- **Screen shake wraps rendering.** `render()` applies a random `translate` (scaled by `screenShake`) inside a `save/restore`; the world is drawn inside it, while HUD/menus are drawn after `restore()` so they don't jitter.
- **Difficulty is curved and capped.** `difficulty = Math.min(4, 1 + gameTime / 90)` — ramps slowly, tops out at 4x. Enemy stats, boss HP, and the boss damage goal all multiply by it.

### Combat & survival

- **Dash (冲刺闪避).** Space/Shift or the round 「冲」 touch button above the E slot (`_renderDashButton`, registered in `skillButtons` as `skill: 'dash'`, available before picking a class) → `_requestSkill('dash')` → `_dash()` → `Player.tryDash()`. The dash travels along `faceX/faceY` (last movement direction) for `dashDuration` 0.18s at `dashSpeed` px/tick; cooldown `dashMaxCooldown` (2.2s, 疾影 talent ×0.8). While `dashTimer > 0` the player is immune and passes through enemies/bullets/boss. **Every player damage site gates on `_canHurt(p)`** (hurt i-frames + dash); a hit blocked by a dash calls `_onPerfectDodge` once per dash: 「闪避!」, `dodgeCount++`, half the cooldown refunded. 幻影冲锋 (`dashStrike`) damages enemies crossed via `_tickDashStrike` (run per guest under `_runAsPlayer`). Snapshot carries `dc`/`dt`/`dg`; guests send `dashMaxCd` in `stats`. Sounds (`whoosh`, `dodge`) are edge-detected in `_sfxTick`. New damage sources must go through `_canHurt`.

Several mechanics exist specifically to keep the game survivable; preserve their intent when editing combat:

- **Hurt i-frames.** On contact damage the player takes a hit then gets `hurtCooldown = 0.6s + hurtCooldownBonus` of invulnerability (renders as a flicker), so overlapping enemies can't drain HP in a single frame.
- **Revive.** When `currentHealth` hits 0 but `life > 0`, the player respawns at center with full HP and `hurtCooldown = 1.5s`. The run ends only when `life` reaches 0.
- **Damage mitigation order** (`Player.takeDamage`): `max(1, dmg − defense − flatDamageReduction)`, then the paladin `shield` absorbs before HP.
- **Invincible potion (`potion_invicible`).** Doubles size/attack/defense for ~10s. Rewritten to store the **added delta** (`invincibleSizeBonus`/etc.) and subtract it on expiry, so talents/upgrades gained *during* the buff are preserved (the old snapshot-and-restore overwrote them). Re-pickup while active only extends the timer.
- **Freeze (`snowflake`).** Sets `enemyFreezeTimer` (frame-based, in seconds), so it pauses with the game and also freezes enemies spawned during the freeze.
- **Bomb (`bomb`).** Range-kills enemies around the player and queues an explosion effect.
- **Hit feedback.** `Enemy`/`BlockBoss.takeDamage` call `flash()` (white overlay while `hitFlash > 0`; it goes negative as a re-flash gap, so per-frame damage blinks instead of staying white). Knockback is velocity (`kbX/kbY`, decays ×0.8/tick) set via `_knockbackDir` / `_knockbackFrom` at hit sites (projectiles, `_dealDamage`, `PiercingArrow`, contact) and applied in `updateEnemies` even while frozen; the boss ignores it, giants take 30%. Hit-stop (`hitStop`, real seconds), `navigator.vibrate` (off when muted) and the red hurt vignette fire only for the **local** player, from `_sfxTick` edge detection on `hurtCooldown`, `killCount` and the boss repel. Single/guest freeze the simulation during hit-stop; the multiplayer host keeps simulating and only holds the rendered frame. Guests learn about flashes from bit 2 of the enemy row's flag field and the boss row's 6th element, and their kills from `kc` in the player snapshot.
- **Lives are capped at `maxLife`** (starts at 3; the 传承 talent raises it). Heart pickups, the every-3-levels bonus and the boss-repel reward all use `Math.min(life + 1, maxLife)`.

### Responsive & touch

The canvas is fullscreen (`100vw × 100vh`); the 800×600 logical world is letterboxed inside it (see "High-DPI canvas" above). **All click/touch handlers must convert coordinates** through the `toCanvas()` helper in `bindEvents()`: client px → backing-store px (`canvas.width / rect.width`) → logical px (subtract `gameOffsetX/Y`, divide by `gameScale`). Preserve this in any new pointer handling, and remember the backing store is in device pixels. **Control modes.** `Game.controlMode` is `'joystick'` (floating virtual stick) or `'tap'` (tap-to-move), stored in `localStorage` `blockrun.control`; keyboard always works. The DOM `#controlOverlay` asks before single/create/join (`withControlChoice` in the load handler) unless `blockrun.controlRemember` is set; the lobby's 操控方式 button reopens it. Touch handlers dispatch each `changedTouches` entry separately so the stick and skill buttons work together. The stick lives in screen space (backing-store px, radius `Game.JOY_RADIUS` CSS px, drawn by `_renderJoystick` after the world transform) and writes an analog vector into `keys._jx/_jy`, which `Player._move` reads and `sendGuestInput` forwards to the host. `Game.skillMode` (`blockrun.skillMode`) is `'tap'` (tap Q/E/冲 to cast, auto-target nearest) or `'aim'` (press a skill button, drag, release; `this.aim`, `_renderAimGuide` / `_renderAimKnob`). Casts go through `_requestSkill(which, aim)` → `_castWithAim`, which sets `player._aim` only for that cast: dash uses it as `faceX/faceY`, `_findClosestEnemies`/`_findClosestTarget` prefer enemies in the ±35° cone (`_inAimCone`), archer Q fires along it. Guests send `aim` in `castSkill`. `_renderSelfMarker` draws a yellow arrow above the local player. The talent menu also reflows between a horizontal 3-column layout (landscape) and a vertical 3-row layout (portrait/narrow). Touch/portrait coordinate handling has historically been a fragile area; test touch input in portrait emulation after touching input or layout code.

### Multiplayer (online co-op)

Host-authoritative. `server.js` is a dumb relay: rooms with a 4-char code, one host (`playerId` 0) and guests; it forwards `state` host→guests and `input` / `castSkill` / `classChoose` guest→host (adding `playerId`). `Game.mpMode` is `null` (single), `'host'` or `'guest'`.

- **Host** runs the full simulation. Guests are extra `Player` objects in `mpGuestPlayers`, driven by the latest input in `mpGuestInputs` (`_applyGuestInputs`, `_checkGuestCollisions`). Every 3rd tick (~20Hz) `broadcastState()` sends `serializeState()`.
- **Acting as a guest: `_runAsPlayer(p, fn)`.** Skill, resource and damage code all read/write `this.player`. To run it for a guest, the host temporarily swaps `this.player` to that guest's `Player` (`_castGuestSkill` for `castSkill` messages; `_tickPlayerResources` for each guest's cooldowns/regen/holy aura every tick). `pendingActions` queued during the swap are tagged with `player` and replayed under the same swap by `_tickPendingActions`. `checkLevelUp()` is deferred while `_actingAs` is set (so no host menu pops mid-swap) and re-run when the swap ends. Any new code that reads `this.player` works for guests automatically if called inside `_runAsPlayer`; never cache `this.player` across ticks.
- **Local Q/E go through `_requestSkill(which)`** (keyboard and touch buttons): guests send `castSkill`, everyone else casts locally.
- **Snapshot format** is compact and quantized (`q1`/`q2`): entities are positional arrays documented above `serializeState()` (`e`, `i`, `p`, `b`, `boss`), players are objects with only their class's resource fields. If you add a field the guest needs, add it there **and** in `applyRemoteState()`.
- **Guest** runs no AI or collisions. `applyRemoteState()` reuses objects by `id` (`_mpSyncList`) and sets interpolation endpoints (`_mpSetTarget`; jumps >150px snap). `_mpInterpolate()` then lerps every entity, other players **and the guest's own player** between snapshots each tick, based on the measured snapshot interval (`mpSnapInterval`). The guest's own position is host-authoritative (no client prediction). Purely visual state (item spin/landing, boss bob, trails) is animated locally. Visual feedback is synced too: each snapshot carries effects created since the last broadcast (`ef`, via `_mpTakeNewEffects`, which marks them `_mpSent`) and recorded particle-spawn calls (`fx`, filled by `_mpRecordFx` inside `spawnHitParticles` / `spawnParticles` / `spawnBurstRing`) that the guest replays.
- **Guest input** (`sendGuestInput`) is sent only when it changes, plus a 250ms heartbeat; it includes `stats` (attack/defense/speed/maxHealth/class, skill levels and max cooldowns) that the host copies onto the guest's `Player`. The guest's own skill level/maxCooldown are authoritative locally; only `cooldown` comes back from the host.
- **Guest talents.** The guest picks talents in its own local menu, then sends `talentChoose { talentId }`. The host runs `_applyTalent` inside `_runAsPlayer(gp)`, so personal effects land on that guest's `Player` and team effects on the shared `Game`. Each guest also gets the host-run auto-attack (`_tickAutoAttack` under `_runAsPlayer`, skipped while the guest is dead).
- **Kill credit.** `Projectile` / `PiercingArrow` carry `owner` (the `Player` who fired). Projectile kills settle through `_runAsPlayer(owner, _onEnemyKilled)`, so life-steal and rage go to the shooter. Score and exp are shared.
